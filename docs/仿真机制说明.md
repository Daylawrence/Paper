# 智能工厂多智能体仿真机制说明

本文说明当前平台里“智能体是什么、停留时间如何设置、路径如何规划、为什么会分批出发，以及训练结果如何导出”。

## 1. 智能体与任务

智能体定义在 [agent.py](e:/毕业论文/毕设/src/factory_gui/model/agent.py)，任务定义在 [task.py](e:/毕业论文/毕设/src/factory_gui/model/task.py)。

- 智能体字段：`id`、`type`、`home`、`speed_cells_per_s`、`capabilities`
- 任务字段：`id`、`type`、`location`、`service_time_s`、`release_time_s`、`due_time_s`、`required_capabilities`

默认场景是 3 类智能体（`agv/forklift/picker`）各 5 个，共 15 个；任务 5 个。

## 2. 停留时间怎么设置

停留时间就是任务服务时间 `service_time_s`（单位秒）：

- 运输任务默认 15 秒
- 重载任务默认 24 秒
- 精细任务默认 18 秒

任务执行流程：到达任务点后进入 `servicing`，计时结束后任务状态变为 `completed`，智能体进入 `returning_home`。

## 3. 路径如何规划

路径算法在 `planner/` 下可切换：

- `astar`：四邻接 + Manhattan 启发，路径最优
- `greedy_best_first`：启发式优先，速度快但不保证最优

统一耗时估计为：

`travel_time = path_length / speed_cells_per_s`

这里 `path_length = len(path) - 1`。

## 4. 为什么会分批出发

分批出发是由规则共同导致的，不是随机现象：

- 任务有释放时间 `release_time_s`，未释放任务不会被分配
- 能力约束：只有满足 `required_capabilities` 的智能体能接该任务
- 单智能体同一时刻只执行一个任务（非 `idle` 不再接单）
- 控制器按当前状态滚动调度，空闲且可执行的智能体先出发

## 5. 任务分配算法与路径算法的组合

任务分配算法与路径算法是两层独立开关，可做组合对比：

- 任务分配：`genetic_assignment`（默认）、`greedy_nearest`、`earliest_due_date`
- 路径规划：`astar`、`greedy_best_first`

可以直接比较不同组合（例如 `genetic_assignment + astar` 与 `greedy_nearest + greedy_best_first`）的完成时间与稳定性。

## 6. 训练结果导出与目标函数曲线

当使用 `genetic_assignment` 运行仿真时，会自动导出训练结果到 `training_results/`：

- 每次分配一份 `dispatch_XXX.csv`
- 每次分配一张目标函数曲线 `dispatch_XXX.png`（代际 best/avg）
- 全局分配轮次曲线 `dispatch_summary.png`
- 运行总结 `simulation_summary.json`

目标函数按“越小越好”优化，核心由预计完工时间、迟期惩罚、行驶代价加权构成，用于近似最小化总体用时。
